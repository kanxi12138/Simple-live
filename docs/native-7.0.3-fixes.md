# 7.0.3 抖音弹幕修复

## 已证实的问题

使用项目现有 Rhino 1.7.15、解释模式、ES6、256 层解释栈、3 秒期限和禁用 Java 类访问的环境执行一次离线签名诊断，原脚本抛出 `ReferenceError: w_0x42f5 is not defined`。脚本在条件块内声明相互调用的函数，依赖的函数提升行为与 Rhino 不兼容；这会在 WebSocket 握手之前失败。

脚本每次调用都会将 window 重置为空对象，所以原初始化条件恒成立。此次将其初始化声明移动至外层函数作用域，保留算法及每次重新初始化的行为。同一离线调用随后返回长度为 16 的字符串，未输出签名值。该结果只证实本地执行恢复，不代表服务器已经接受签名。

## 连接与恢复

- 准备一次连接时合并房间响应中的必要会话 Cookie，统一房间真实 ID、访客标识、UA、Referer 及签名参数；会话只保留于本次连接，不覆盖保存的账号 Cookie。
- 首次连接和最多两次重连使用主、备、主服务器顺序，每次重新准备参数；取消会传播至接口请求和签名指令检查。
- 抖音改用 OkHttp 公开 pingInterval 的 5 秒 WebSocket Ping；移除原来当作普通二进制消息发送的 hb。该 Ping 是空负载，与旧版带 hb 负载的 Ping 不完全等同；此次没有实连验证其平台兼容性，也未调用 OkHttp 内部 API。
- 继续按 PushFrame/Response 字段处理 gzip、聊天消息和 ACK；ACK 发送失败明确断开。单条聊天消息格式错误不再导致整个连接退出，外层帧或解压损坏仍触发有限重连，保留原有大小限制。
- 保留会话准备、签名、握手、解压、消息解析及连接关闭的失败阶段和可用的 HTTP 状态，不再用最终通用提示覆盖失败原因。诊断不记录 Cookie、完整 URL、签名或聊天内容。
- 抖音竖屏弹幕区和弹幕设置面板增加“重连弹幕”，不重新解析或刷新视频。连接使用独立代次，旧任务完成释放后再建立新连接，旧回调不能更新新房间或新连接。

## 范围与检查边界

按用户最新要求，FLV 播放故障本轮略过；未更改播放源选择、CDN 名单或其他正常播放线路。

执行代码审查、一次修正前与一次修正后的离线签名诊断，以及必要 release 编译和安装检查。没有主动连接直播弹幕，没有运行测试套件、lint、独立类型检查或手机交互验收。弹幕实际收取、备用服务器和心跳兼容性仍未经运行验证。
