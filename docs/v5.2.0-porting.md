## Implemented scope

- Removed the background audio control, state synchronization, Android bridge/lifecycle takeover, service registration, Media3 dependencies and dedicated permissions from saved and generated Android projects.
- Refined mobile top bar, search, follows and settings spacing, typography, touch targets and button states. Existing portrait control rows, orientation controls, 280px danmaku panel and scrolling remain.
- Mobile Douyin search trims input, routes digits to room details and keywords to live-room search. Request generations invalidate stale results on input changes, closure and platform changes.
- Douyu: runtime search device ID, response parsing and errors, live/loop detection, H5 signing flow, actual quality and CDN order. Android retains one native socket, with stale callback guards and binary frame validation; login/group/heartbeat/STT escaping retained where equivalent.
- Huya: mobile page metadata, actual rates/CDNs, TUP3 CDN token request, AntiCode and playback UA. Danmaku uses room channel identifiers, TARS registration/chat decoding and reference heartbeat.
- Douyin: runtime cookies, enter/reflow APIs and page fallback, SDK quality names and URLs, fixed-baseline WebSocket signing JavaScript in the existing Rust/QuickJS environment, real room/user identifiers, Protobuf/gzip decoding, heartbeat and raw internal_ext ACK payload.
- Bilibili: runtime buvid/user cookies, WBI signing, real room resolution and returned playback options. Replaced blocking danmaku transport with cancellable asynchronous server/token/authentication, heartbeat, zlib/Brotli and framed message handling.
- Preserved Tauri command names and existing result fields, adding optional playback options and request headers. The shared local proxy captures each stream context, forwards FLV headers, and rewrites HLS playlists, segments, map/key URIs and relative URLs. Player/proxy/danmaku generations prevent old room callbacks from rendering into a new room.

## Search and login repairs

- Huya skips malformed search entries without discarding valid results.
- Douyin preserves platform errors and uses the existing Android official-site login session at runtime. Login credentials are not embedded in source.

## Account-name search and follower ordering


- Added `search_douyin_accounts`, using the official user-search endpoint `/aweme/v1/web/discover/search/` with `search_channel=aweme_user_web` and the existing runtime login cookie. Account results include UID/sec_uid, display Douyin ID, avatar, follower count, live status and separate optional room identifiers. This is an extension outside the pinned Dart live-search baseline.
- Mobile search requests accounts and the existing live/numbered-room path concurrently. It combines results by explicit account/room identity, preserves partial successes and errors, and rejects late updates from obsolete requests. Offline accounts remain visible; unknown status is explicit; playback is enabled only for confirmed live rows with room identifiers.
- The single combined list sorts actual follower counts descending, with missing counts last and stable ties. Audience and like counts are not used as follower counts. Live-search metadata adds optional identity/follower fields without changing existing command names.
- Douyin input placeholder is exactly `输入直播关键字或抖音号`. Account identity and follower/status labels are displayed in the existing mobile result rows.
